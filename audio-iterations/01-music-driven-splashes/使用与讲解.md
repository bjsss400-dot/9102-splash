# 你的 Music / Audio Mechanic

## 怎么打开

把整个 `bigger-splash-audio` 文件夹用 VS Code 打开，在 `index.html` 上选择 **Open with Live Server**。不要只双击 HTML，否则浏览器可能不允许加载音乐。

点击画面开始。前 1.4 秒用来学习平均音量，之后轻拍和重拍会触发不同大小的水花。按 **M** 暂停或继续；按 **1–4** 切换时段；点击水池、左右拖动仍使用组员的交互。音乐暂停时，已经产生的水花仍会完成自己的动画。

配乐是本次生成的原创演示曲 **Poolside Study**：24 秒循环，每 3 秒有一个强拍，中间有较轻的音符。不是录音采样，也不是你们之前提供的歌曲。

4. 将 README 中你的音频技术、配乐来源、参考链接与 AI 使用说明合并进小组 README，填上真实姓名。

完整文件夹已经把上述修改接好，可以直接运行。`index.html` 改用随包附带的库；`style.css` 加了按窗口比例显示画布的规则。合并时这些属于小幅整合改动，可以与组员的最新版比较后保留。

不要用这个包中的旧 Perlin 文件覆盖组员后来完成的版本。你发来的文件中 `setupVariation()`、水面纹理和水线仍为空，这是这份源文件本身的状态。音频可以直接与保留原接口的 Perlin 新版配合。

## 你需要理解的逻辑

`audioTrack` 保存音乐；`audioAmplitude` 读取它的实际响度；`audioState` 保存播放状态、当前响度、平均响度和最近 60 帧记录。

`updateAudioMechanic()` 每帧读取声音，交给 `analyseAudioLevel()`：

- 当前响度变化较快，用 lerp 平滑抖动。
- 平均响度变化较慢，表示这段音乐“平时多响”。
- 当前响度超过平均值一定幅度，就开始收集一个 100 毫秒的短波峰。
- 计算波峰比平均值高多少，分成小、中、大，传给 `triggerSplash()`。
- 两次自动水花间至少间隔 420 毫秒，而且声音必须回落后才能再次触发，避免持续响声不断冒水花。

所有自动水花都在同一位置、同一水深产生，三档 power 分别为 0.55、1.1、1.85。这样“更大的水花”来自声音强度，而不是鼠标位置或随机大小。图中的示例曲线不是这个项目的实测结果；本实现的参数是对随包的原创曲调试的。

`drawAudioMeter()` 在右上角画 60 根小竖线，下面画当前响度细条。60 帧在 60 FPS 时约等于一秒，低帧率时会更长；它不是 FFT 频谱。

## 展示时可以怎样解释

“我的部分是 Audio Mechanic。我把音乐的响度变化转成水花，让原画中静止的一瞬间随着音乐反复发生。我使用 p5.Amplitude 测量音轨，用两个变化速度不同的 lerp 分别得到当前响度和平均响度。出现比平均值更强的短波峰时，代码会触发水花；差距越大，水花越大。我还做了启动缓冲和冷却时间，避免误触发。我的模块只决定何时触发以及强度，水花的生命周期和外观继续由组员的模块负责。”

这段话描述了代码的运行方式。提交和展示时也要说明 Codex / ChatGPT 协助了代码、测试和配乐生成，并结合你自己实际理解、调试和修改的过程来讲。

## 调整音乐

换曲时先改 `AUDIO_TRACK` 的路径，试播后再调整 `gain`（检测灵敏度，不是扬声器音量）和分档阈值。并不是所有歌曲都会每三秒出现大水花：三秒来自当前配乐的强拍间隔，视觉代码没有写死这个节奏。
